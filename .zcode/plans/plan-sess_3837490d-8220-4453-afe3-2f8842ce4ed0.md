# Weekly Digest: Cap at 10 Items + Ranking + Dedicated Digest Page

## Analysis summary (what the data showed)

The Sep 7 digest run (`bb0ce9f4`) contained **28 items** sent as multi-part messages. Across the catalog (276 items):

- **GitHub stars** are the strongest per-item signal but sparse: only 76/276 items have stars; within the Sep 7 digest, 24/28 were null — pure stars ordering surfaces 4 real projects then degenerates into arbitrary tie-breaks.
- **Mention count / cross-channel mentions** are rare and meaningful at catalog level (only 4 items with 3+ candidates, 14 mentioned in 2+ channels) but barely discriminate within one week (27/28 items had 1 mention).
- **LLM confidence is useless for ranking** (uniform 0.94–0.98 across all star buckets); it measures extraction quality, not interestingness.
- **Kind-diversity matters**: both simulated top-10 cuts dropped entire kinds (OTHER_TECH guides like Passkeys, TEE, quantization).

Chosen approach: **composite score + kind-diversity slot reservation**, overflow via a **dedicated digest page**.

## Changes

### 1. Config: `apps/service/src/config.ts`
- Add `DIGEST_MAX_ITEMS` env var (int, validated, clamped 1–20, **default 10**).

### 2. Ranking module: new `apps/service/src/digest/ranking.ts`
Pure, unit-testable function `rankDigestItems(items) -> items` (top N + rest):

- Compute per item:
  - `channelCount` = distinct channels of presentation candidates in the run window (query in coordinator, pass in)
  - `mentionCount` = candidate count in window
  - `starsScore` = `log10(githubStars + 1)` (null → 0)
  - `recency` = `lastMentionedAt` within window
- Composite score: `2*(channelCount-1) + 0.5*(mentionCount-1) + starsScore/5` (log scale of 44k stars ≈ 4.6/5 ≈ 0.92 — a 2-channel mention outranks it slightly; tune constants in tests using the Sep 7 data as fixture).
- **Kind-diversity pass**: first take the single best-scoring item of each kind present in the week (fills 3–6 slots), then fill remaining slots by global score desc, skipping items whose kind already occupies ≥ `ceil(maxItems * 0.4)` slots. Final tie-break: `lastMentionedAt desc, id asc` (deterministic).
- Excluded from scoring: confidence (proven non-discriminative).

### 3. Coordinator: `apps/service/src/digest/coordinator.ts`
- In `prepareRun()` (item query at lines 114–143), also fetch per-item candidate mention/channel counts for the window.
- Apply `rankDigestItems`, take top `DIGEST_MAX_ITEMS` for the post; **keep all eligible items in `WeeklyDigestItem` snapshots**, with `ordinal` assigned by rank (selected items first, then the overflow, so the snapshot doubles as the full list for the new page). Add a boolean/flag or use a `selectedCount` field on `WeeklyDigestRun` to know the cut line (prefer a new `selectedCount Int` column on `WeeklyDigestRun` — avoids schema change on items).
- Prisma migration: add `selectedCount` to `WeeklyDigestRun` (nullable for old runs; backfill with itemCount).

### 4. Renderer: `apps/service/src/digest/renderer.ts`
- Render only ordinals `0..selectedCount-1`; with ≤10 items the existing char limits (3500/3900) should yield a single part — keep the multi-part packing as a safety net, no removal.
- Footer: keep "All projects" link, add a second line when there is overflow: "See all N items from this week →" pointing to the digest page URL (`{DIGEST_SITE_ORIGIN}/digest/{runId}` or `/digest/latest`).

### 5. Web: dedicated digest page
- API: `apps/service/src/server.ts` + `apps/service/src/catalog/queries.ts` — `GET /v1/digest/latest` (and `/v1/digest/:id`) returning run metadata + all `WeeklyDigestItem` snapshots with selected/in-overflow flag (ordinal < selectedCount).
- Frontend: `apps/web/app/routes/digest.$id.tsx` (plus `/digest/latest` resolving the newest run): render cover, date range, items grouped by kind (same order as digest), visual "featured in Telegram post" marking for the top-10, and overflow items below. Match existing catalog styling.
- Renderer footer links to `/digest/latest`.

### 6. Tests
- Unit tests for `ranking.ts` with fixtures mirroring the real Sep 7 data (28 items, 24 null-star, one 2-mention item, 44k-star item) asserting: top-10 composition, every kind represented, deterministic tie-breaks, `DIGEST_MAX_ITEMS` clamping.
- Renderer test: single-part output with 10 items + overflow footer link; regression for >10 overflow rendering.
- Coordinator test updated for `selectedCount` persistence.
